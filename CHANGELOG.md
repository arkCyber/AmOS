## [Unreleased]

### Added
- **Demo incoming-call injection (`amos-telephony` + `proto` + `amos-tauri` + `frontend-ts`, 2026-09-04)**: closes the last demo gap so the incoming-call surface is actually operable by hand, not just DOM-tested. `proto` adds `SimulateIncoming{number}` → `CallIdMsg` (mock-only; a real provider returns `Unavailable`); `TelephonyService::simulate_incoming` reuses the existing injector and drives the `Watch` stream (Ringing Incoming). Tauri exposes `telephony_simulate_incoming`; the `PhoneApp` idle dialer gains a faint **"模拟来电"** dev affordance (rings an incoming call from the dialed or a demo number) that the system `IncomingCall` overlay then presents for Answer/Decline/record. Tests: telephony unit now **45** (SimulateIncoming RPC → Watch Ringing) + `PhoneRecording.test.tsx` demo-trigger test; workspace `cargo check` clean.
- **Telephony broadcast audit fixes (`amos-telephony`, 2026-09-04)**: hardened signalling-consistency gaps found by audit so **every** call-state transition is broadcast on `Watch`. (1) `MockTelephonyProvider::answer` now **broadcasts `Connected`** — answering an incoming call previously left the `Watch` stream silent (contradicting the `telephony_answer` contract). (2) Recording is a **first-class broadcast call-state**: `start_recording`/`stop_recording`/`simulate_recording_failure` emit `ProviderEvent::RecordingChanged`. (3) Recording broadcasts carry the call's **true `direction`** (an answered *incoming* call is not re-tagged Outgoing). (4) A **local hang-up now broadcasts `LocalEnded`** (previously `end()` was silent), making local end symmetric with remote end / answer / record. All verified with new unit tests; telephony unit count now **47** + 2 UDS e2e; `clippy --all-targets -D warnings` clean.
- **Call telephony — end-to-end loop closure (`amos-telephony` + `amos-ai` + `amos-tauri` + `frontend-ts`, 2026-09-04)**: a desktop dial is now actually operable through dial → Active → record → hang up. `TelephonyService` gains demo auto-connect (`demo_server()` used by the `amos-ai` daemon; outgoing *regular* calls reach `Active` after a short ring via the mock "network answers"; emergency calls stay ringing; hung-up-before-connect is ignored) while `mock_server()` stays deterministic for the headless e2e harness. `amos-tauri` opens a **long-lived `Watch` stream** and forwards each call-state event to the WebView as `telephony-event` (`spawn_telephony_watch`, reconnects with bounded backoff), adds `telephony_answer`, and extends `TelephonyCallPayload` with `direction`. `PhoneApp` now subscribes and enters a real "In call"/talking screen when its dialed call connects (enabling the record toggle) and returns to the keypad on End; new **system incoming-call overlay** (`IncomingCall`) shows Ringing → Answer/Decline and, once answered (Active), a compact in-call banner with record toggle + Hang up. i18n en/zh (`phone.talking/incoming/answer/decline/hangup`). Tests: telephony unit now **42** (demo auto-connect → Active) + updated `PhoneRecording.test.tsx` (Active-via-event enables record) + new `IncomingCall.test.tsx` (ringing/answer→recordable banner/decline). Real audio capture + on-device incoming injection remain future audio/device work.


- **Call recording — full-stack capability (`amos-telephony` + `proto` + `amos-tauri` + `frontend-ts`, 2026-09-04)**: 通话录音 as a first-class, contractual feature across every layer. Domain kernel (`session.rs`) gains a `RecordingState { Off, On, Failed }` on `Call` with whitelisted transitions — recording is legal only while a call is **Active** and **non-emergency** (emergency/110-112 lines are a hard refusal), auto-reset to `Off` on hang-up, and a device `Failed` state is surfaceable + retryable. `TelephonyProvider` seam adds `start_recording`/`stop_recording` (provider decides allow/deny via a consent/jurisdiction policy knob; domain denies before the provider is consulted). `proto/telephony.proto` adds a `RecordingState` enum, `CallSnapshot.recording`, and `StartRecording`/`StopRecording` RPCs returning the authoritative snapshot; `CallSnapshot` records carry `recording`. gRPC `TelephonyService` maps it all; Tauri bridge exposes `telephony_start_recording`/`telephony_stop_recording` (+ `TelephonyCallPayload.recording`). `PhoneApp` in-call screen offers a record toggle (start/stop, live "正在录音" indicator) that mirrors the daemon's authoritative state and never claims a recording the OS declined. i18n en/zh (`phone.record*`). Tests: 41 unit (recording domain/provider/service: legality, emergency-forbid, policy denial, failure→retry, end-resets, status-carries-recording, RPC error mapping) + 3 `PhoneRecording.test.tsx` DOM tests. Real audio capture stays with the future audio pipeline; this delivers the state machine + contract + UI control.

DOM tests (`MessagesApp.test.tsx`).

New dedicated `messages.test.ts` covers every export (seed/append/quote/normalize-cap/clear/remove/time&day helpers/unread/markRead/markAllRead/constants).

- **Shared outgoing-call hook (`frontend-ts`, 2026-09-04)**: extracted `lib/useOutgoingCalls.ts`, now used by both `ContactsApp` and `PhoneApp` — it owns call-history state and derives the Frequent ⭐/Recent quick-dial lists (name-resolved from live contacts) and the `recordOutgoing` (write calllog + raise phone notification) side-effect, removing the duplicated logic the two apps previously each inlined. Dedicated hook tests (`useOutgoingCalls.test.tsx`): name-resolved lists, and record→calllog+notification.

DOM tests (`PhoneApp.test.tsx`).

New `ContactsApp` UI: search, add (with validation hint), favorite toggle, two-tap delete, and "call" out via the telephony bridge (graceful "daemon offline" when not bridged). Full unit tests (`contacts.test.ts` — 16) plus DOM interaction tests (`ContactsApp.test.tsx` — 4: list, call-offline, two-tap delete persists, add-validation). Registered in the app grid + i18n en/zh.
- **Contacts edit + duplicate guard + grouping (`frontend-ts`, 2026-09-04)**: `ContactsApp` can now edit an existing contact (✏️ prefill → save via `editContact`); adding is refused when the number already exists (`contactsWithPhone`, digit-normalized incl. `+CC`/bare suffix match → "duplicate" hint); the list is grouped by letter (A–Z / `#`) with colored initial avatars (`contactLetter`/`groupContacts`/`avatarHue`). New pure helpers all unit-tested; contacts.ts stays at 100% function coverage.
- **Call history + recents (`frontend-ts`, 2026-09-04)**: new `lib/calllog.ts` domain — pure, durable `amos.calllog`: `normalizeCallLog` (newest-first, keeps history for frequency stats, caps at 60, repairs corrupt stores), `recordCall`, `recentNumbers` (distinct quick-dial list), `frequentNumbers` ("常用"), `logNameFor`, `callDigits`. Successful bridged calls from `ContactsApp` are recorded (functional update, no stale-closure loss), and "Frequent ⭐" (top-by-frequency) and "Recent" quick-dial strips appear (number → contact-name lookup). - **Radio / connectivity（`amos-radio` + `amos-tauri` + `frontend-ts`, 2026-09-04）**: new transport-agnostic domain crate `amos-radio` — `RadioMode`/`RadioSnapshot`, a `RadioProvider` seam + deterministic `MockRadioProvider`, and a `RadioManager` owning the policy (Airplane mode cascades Wi-Fi + Bluetooth off; the non-airplane radios are refused while Airplane is on; `set` returns the authoritative snapshot). 10 unit tests. The System UI drives it through in-process `radio_status`/`radio_set` Tauri commands (real Wi-Fi/Bluetooth on the no-UI Android base are Android system services reachable from the System UI APK, so unlike telephony these do not round-trip through the headless daemon), mirroring each snapshot back into the durable `amos.settings` store (cross-window broadcast). Notification-center wifi/bluetooth/airplane tiles go through the backend, with a same-policy `flipRadio` fallback outside Tauri and an authoritative `radioStatus` sync on open. A real Android backend is scaffolded as `AndroidRadioProvider` under the `android` feature (JNI `WifiManager`/`BluetoothAdapter`; `cargo check --features android` validates it compiles; on-device hookup pending). - **Reactive-store cross-window correctness (`frontend-ts`, 2026-09-04)**: `useStoreValue` now honours the authoritative `store-updated` payload from the Rust store instead of re-reading this window's (possibly stale) `localStorage`, and mirrors it back into `localStorage` for consistency. End-to-end tests simulate a second Tauri window pushing a `store-updated` event and assert the hook re-renders with the authoritative value and correctly resets on removal.
- **Network time calibration (`amos-timesync`, 2026-09-03)**: transport-agnostic `TimeSource` seam (`MockTimeSource` deterministic, `HostClock` offline fallback) feeding a `SyncedClock` that turns an authoritative network time into a signed host-clock offset, applies it to `now()`, rejects implausible times (plausibility window 2000–2100), and atomically persists the last-known-good offset (corrupt/missing file degrades gracefully). A `Timekeeper` runs the periodic sync loop. Real SNTP query is a `ntp` feature (`NtpTimeSource` via `sntpc` + `sntpc-net-std`, blocking work on `spawn_blocking`); a `ntp_probe` example does a live query. Deps: `async-trait`, `thiserror` (+ optional `sntpc`/`sntpc-net-std`).
- **Supervised periodic time sync (`amos-supervisor` `timesync` feature, 2026-09-03)**: optional background wall-clock calibration orchestrated alongside daemon supervision. Default build and behaviour unchanged; enabling the `timesync` feature and `AMOS_TIMESYNC=1` at runtime spawns a periodic `SyncedClock` loop (`AMOS_NTP_SERVER` for real SNTP, `AMOS_TIMESYNC_STATE`/`AMOS_TIMESYNC_INTERVAL_SECS` optional), exposes live calibrated-time status (`TimeSyncHandle::report()`: corrected now / offset / staleness, printed at startup, on SIGUSR1, and before shutdown), and exports the state path to supervised children via `AMOS_TIMESYNC_STATE` so any daemon can load the last-known-good calibrated clock. Added to `make gated-check`.
- **App store core engine (`amos-appstore`, 2026-09-03)**: transport-agnostic `AppManifest` catalog + `Version`, sha256 integrity check, and an `AppStore` engine driving download → verify → install / upgrade / uninstall over a pluggable `StoreProvider` (deterministic in-memory `MockStoreProvider` today) with a JSON-persisted installed registry. Publish contract + developer onboarding in `docs/appstore.md`.
- **App store CLI (`amos-appstore-cli`, 2026-09-03)**: headless terminal driver over the same engine (demo/catalog/search/install/upgrade/uninstall/status), mirroring `amos-mail-cli`; `--catalog <URL>` (with `--features live`) swaps the offline demo for the real HTTP backend.
- **App store HTTP backend (`amos-appstore` `live` feature, 2026-09-03)**: `HttpStoreProvider` fetches a remote `MockCatalog` JSON catalog + downloads packages over HTTP (ureq in `spawn_blocking`); feature-gated so the default build stays offline-green. Both the CLI (`--catalog`, `--features live`) and the Tauri `StoreBridge` (`AMOS_APPSTORE_CATALOG`, `--features appstore-live`) can select it at runtime via a type-erased `Box<dyn StoreProvider>`.
- **App store publisher signing (`amos-appstore`, 2026-09-03)**: Ed25519 signing/verification of app manifests (`DeveloperKey`/`sign_manifest`/`verify_manifest_signature`, `publisher` field); the engine verifies a signed manifest's signature before install/upgrade and refuses mismatches (`BadPublisherSignature`). Dep: `ed25519-dalek`.
- **Web-bundle installer (`amos-appstore`, 2026-09-03)**: `webinstall::WebInstaller` unpacks a verified `tar.gz` web-bundle (`index.html` + assets + `amos-app.json`) into `<root>/<id>/`, validates the entry file, writes `manifest.json`, and uninstalls; `tar` refuses `..`/absolute paths. Deps: `tar`, `flate2`.
- **Web-bundle server resolver (`amos-appstore`, 2026-09-03)**: `serve::{resolve_request, content_type_for}` maps a host request path safely onto a file inside an installed bundle (refuses traversal/`..`, falls back to `index.html`, returns MIME + `nosniff`) — the server-side gate a future custom-protocol host needs.
- **Engine web-bundle install (`amos-appstore`, 2026-09-03)**: `AppStore::with_web_install_dir(dir)` makes `install`/`upgrade` of a `tar.gz` bundle also unpack it to `<dir>/<id>/` (and `uninstall` removes it); a bundle that can't unpack fails the install and isn't recorded. Tests cover unpack→uninstall and broken-bundle rejection.
- **StoreBridge bundle serving (`amos-tauri`, 2026-09-03)**: `StoreBridge` reads `AMOS_APPSTORE_INSTALL_DIR` and configures the engine's web-install dir; new command `appstore_bundle_resource(id, path)` returns a bundle file as base64 + MIME (sanitised by `serve::resolve_request`), so a local web-bundle can be rendered without a custom protocol. Headless-tested.
- **App Store System-UI page (`frontend-ts`, 2026-09-03)**: new "App Store" app (`components/StoreApp.tsx`, registered in `APPS`/`COMPONENTS`) browses the catalog (offline demo or HTTP) and install / update / uninstall through the `store*` bridge, with graceful offline fallback outside the Tauri shell. i18n zh/en.
- **Dynamic home registry for store apps (`frontend-ts`, 2026-09-03)**: store-installed apps become persistent home-screen tiles (`lib/storeApps.ts`, `store:<mid>` ids merged into `amos.home.layout`); `HomeDock`/title/`AppComponent` resolve them and tapping opens a placeholder container (`components/ExtApp.tsx`) until a real runtime host (installer) lands. Store page changes notify the shell live.
- **Durable system state store (`amos-tauri` + `frontend-ts`, 2026-09-03)**: `SharedStore` persists every `amos.*` mutation to disk (`$AMOS_STATE_FILE`, default `~/.amos/state.json`); on boot the shell hydrates localStorage from it, so state recovers even after localStorage is cleared.
- **Permission ledger (`frontend-ts`, 2026-09-03)**: `lib/permissions.ts` — pure, immutable, durable (store-backed `amos.permissions`) grants of sensitive capabilities (camera/microphone/location/notifications) per app; query/grant/revoke + normalize. UI dashboard + enforcement wiring next.
- **Privacy & permissions dashboard (`frontend-ts`, 2026-09-03)**: new "privacy" app (`components/PermissionsApp.tsx`, in `APPS`) lists each capability with its granted apps (revocable) and allow/deny toggles for the built-in apps that request it; changes persist in the durable store.

Mic/location call sites still to gate.

None call `getUserMedia({audio})` before the capability is granted; allows persist (revoke via Privacy).

## Template for new releases

When creating a new release:

1. Update version numbers in `Cargo.toml` across all crates
2. Update version in `tauri.conf.json`
3. Add corresponding section below with:
   - Date in YYYY-MM-DD format
   - Clear categorization of changes
   - Links to related issues/PRs
4. Update any affected documentation

### Commit message format:

```
chore(release): v0.X.Y

- Brief description of major features
- Link to release notes
```

### Release checklist:

- [ ] All tests passing (`make test`)
- [ ] All linting clean (`make lint`)
- [ ] CHANGELOG.md updated
- [ ] Version numbers updated
- [ ] Documentation updated if needed
- [ ] Security audit completed
- [ ] Tagged in git: `git tag v0.X.Y`
- [ ] GitHub release created with release notes
