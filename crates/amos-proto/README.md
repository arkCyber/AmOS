# amos-proto — shared gRPC (tonic) types and transport helpers

The generated Rust types for every `.proto` in the repo, plus the socket-path helpers that
keep the daemon and its clients agreeing on where to connect. Part of
**[Amos](../../README.md)**. Generated reference: [`docs/api-grpc.md`](../../docs/api-grpc.md).

> ⚠️ Amos is a research prototype — not qualified for safety-critical use (see the
> [root README](../../README.md)).

## What it is

- One module per contract — `ai_agent`, `translate`, `amos_sensor`, `amos_telephony`,
  `amos_governor`, `amos_privacy`, `amos_netguard`, `amos_telemetry_spy`, `amos_link`,
  `android_compat` — generated by `build.rs` on every build, so the wire can never drift from
  the `.proto`.
- `socket`: the path resolution both sides use (`AMOS_SOCKET`, then the platform default), so
  a client cannot end up looking at a different socket than the daemon serves.
- No logic beyond that: this crate is glue, and it is deliberately thin so that a reviewer can
  read the whole surface.

It is **not** a service implementation and holds no state.

## Layout

| file | what |
|---|---|
| `proto/*.proto` (repo root) | the single source of truth for every service |
| `build.rs` | `tonic-prost-build` wiring (compiles the protos into `src/`) |
| `src/lib.rs` | module declarations + the socket helper |

## Build & test

```bash
cargo test -p amos-proto                 # includes the build-script/proto check
cargo build -p amos-proto                # regenerates the types
node scripts/proto-doc.mjs --check       # docs/api-grpc.md matches proto/*.proto
cargo clippy -p amos-proto --all-targets -- -D warnings
```

## Examples

```bash
# Print where every client will connect, and build a sample request type.
cargo run -p amos-proto --example contract_selfcheck
```

| example | shows |
|---|---|
| `contract_selfcheck` | the resolved socket path for the daemon (with `AMOS_SOCKET` override behaviour), plus a constructed request/response type from the generated modules — proof that the contract compiles into usable Rust on this host |

## Honest boundaries

- **Generated code**: nothing here is hand-written except the module list and the socket
  helper; a change belongs in the `.proto`.
- **`bitcode`/JSON transcoding is not provided**: clients speak gRPC over the socket.
- **`protoc` is required to build** (`brew install protobuf` / `protobuf-compiler`); the
  build fails loudly without it rather than shipping stale types.
- **The example does not start a server**: it proves types and paths, not behaviour.
